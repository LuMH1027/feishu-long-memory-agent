# 1. 飞书查询卡片与跨库联动构建

## 目标
打破数据孤岛，使得飞书侧能够查询解析并展现 CLI 侧的资产记忆。

## 涉及文件
- `backend/routers/feishu.py`
- `backend/routers/memory.py`
- `feishu_bot/card_templates/`

## 开发完成标准
- 完成飞书 webhook 中的查询意图识别。
- 定义“历史 CLI 命令卡片”和“工作流执行卡片”模板（如返回带复制交互和步骤细项的交互式响应形式）。
- 通过飞书的指令查询或自然语言 `@` 能顺利拉取包含目标上下文的指令。

## 测试用例思路
```bash
# 模拟向 API 后端发起带项目上下文意图的查询
curl -X GET "http://localhost:8000/api/v1/memory/search?query=启动webapp容器"
# 预期可调取 CLI 侧记录的容器启动指令与历史成功率，并以卡片 JSON 结构反馈。
```

## 2026-04-29 实现记录

本阶段已完成飞书侧跨库查询入口：

1. 新增 `backend/routers/feishu.py` 中的 `POST /api/v1/feishu/memory/query`。
2. 查询会复用统一记忆检索能力，返回卡片化 JSON，而不是只返回原始文本。
3. 当前支持三类卡片：
   - `cli_command`：展示历史命令、使用次数、成功次数、目录上下文。
   - `workflow`：展示工作流名称与步骤列表。
   - `decision`：展示项目决策、结论、原因、推荐参数与废弃参数。
4. 单元测试覆盖了飞书自然语言问题命中 CLI 历史命令的场景，例如“谁知道 api-server 怎么重启？”可返回 `kubectl rollout restart deploy/api-server -n prod`。

接口示例：

```bash
curl -X POST "http://localhost:8000/api/v1/feishu/memory/query" ^
  -H "Content-Type: application/json" ^
  -d "{\"query\":\"api-server 怎么重启\",\"chat_id\":\"chat-1\"}"
```
