# 3. 检索关联与主动推送策略

## 目标
探索隐性体验优化，不被 @ 仍能在关键时刻抛出有价值信息。基于飞书的话题追踪推荐 CLI 执行步骤或前置讨论记录。

## 涉及文件
- `feishu_bot/` 相关事件与监听模块
- `backend/routers/feishu.py`

## 开发完成标准
- 对飞书群组的消息长尾流增加监听和摘要分析。
- 当出现如 `部署 webapp`, `重启 api-server`, `备份订单库` 的话题时，调用关联检索。
- 若命中高度相关（Score 达标）的具体 CLI 指令历史或决策，推送“历史讨论摘要或推荐操作”。

## 测试用例思路
```bash
# 模拟普通对话：
# 用户A：谁知道 api-server 的重启流程？
# 用户B：我记得好像要带某个特定参数。
#
# 预期：
# 机器人不需要被 @，自动抓取对话关键词，推送以往的命令记录和相关决策卡片：
# 【提示】检测到讨论，历史上 api-server 重启的高频命令为 kubectl rollout restart deploy/api-server -n prod
```

## 2026-04-29 实现记录

本阶段已完成飞书消息分析入口：

1. 新增 `POST /api/v1/feishu/message/analyze`。
2. 如果消息包含决策语义，系统执行 `decision_stored`，将消息转为项目决策记忆。
3. 如果消息包含查询或操作语义，例如“怎么、流程、命令、启动、部署、重启、清理”，系统执行 `suggest_cards`，返回候选推送卡片。
4. 如果消息显式 `mentioned=true`，即使不是强查询句，也会尝试检索相关记忆。
5. 当前返回的是可测试的卡片 JSON；如果设置 `FEISHU_AUTO_REPLY=true`，会通过官方 `lark-cli` 自动把结果以文本消息发回群里。

接口示例：

```bash
curl -X POST "http://localhost:8000/api/v1/feishu/message/analyze" ^
  -H "Content-Type: application/json" ^
  -d "{\"content\":\"谁知道 api-server 怎么重启？\",\"chat_id\":\"chat-1\"}"
```

### larksuite/cli 接入方式

本项目的飞书发送层已经改为调用官方 `larksuite/cli`：

```bash
lark-cli im +messages-send --as bot --chat-id "oc_xxx" --text "消息内容" --format json
```

对应代码位置：

- `feishu_bot/lark_cli.py`：封装 `lark-cli im +messages-send`。
- `backend/routers/feishu.py`：在 `_send_group_text()` 中调用该适配器。
- `POST /api/v1/feishu/message/push`：直接使用 `lark-cli` 主动推送文本消息。
- `POST /api/v1/feishu/message/analyze`：在 `FEISHU_AUTO_REPLY=true` 时自动回复查询结果或决策入库确认。

本地接入前需要先完成：

```bash
lark-cli config init
lark-cli auth login
```

环境变量建议：

```env
FEISHU_AUTO_REPLY=true
LARK_CLI_BIN=lark-cli
LARK_CLI_TIMEOUT_SECONDS=15
```

如果未安装或未认证 `lark-cli`，接口不会影响数据库写入，但 `reply.status` 会返回 `error`，并提示先安装或认证。
