# 3. 检索关联与主动推送策略

## 目标
探索隐性体验优化，不被 @ 仍能在关键时刻抛出有价值信息。基于飞书的话题追踪推荐 CLI 执行步骤或前置讨论记录。

## 涉及文件
- `feishu_bot/` 相关事件与监听模块
- `backend/routers/feishu.py`

## 开发完成标准
- 对飞书群组的消息长尾流增加监听和摘要分析。
- 当出现如 `部署 webapp`, `重启 api-server`, `备份订单库` 的话题时，调用关联检索。
- 若命中高度相关（Score 达标）的具体 CLI 指令历史或决策，推送“历史讨论摘要或推荐操作”。

## 测试用例思路
```bash
# 模拟普通对话：
# 用户A：谁知道 api-server 的重启流程？
# 用户B：我记得好像要带某个特定参数。
#
# 预期：
# 机器人不需要被 @，自动抓取对话关键词，推送以往的命令记录和相关决策卡片：
# 【提示】检测到讨论，历史上 api-server 重启的高频命令为 kubectl rollout restart deploy/api-server -n prod
```

## 2026-04-29 实现记录

本阶段已完成飞书消息分析入口：

1. 新增 `POST /api/v1/feishu/message/analyze`。
2. 如果消息包含决策语义，系统执行 `decision_stored`，将消息转为项目决策记忆。
3. 如果消息包含查询或操作语义，例如“怎么、流程、命令、启动、部署、重启、清理”，系统执行 `suggest_cards`，返回候选推送卡片。
4. 如果消息显式 `mentioned=true`，即使不是强查询句，也会尝试检索相关记忆。
5. 当前返回的是可测试的卡片 JSON，后续真实飞书机器人只需要把该 JSON 转换为飞书交互卡片即可。

接口示例：

```bash
curl -X POST "http://localhost:8000/api/v1/feishu/message/analyze" ^
  -H "Content-Type: application/json" ^
  -d "{\"content\":\"谁知道 api-server 怎么重启？\",\"chat_id\":\"chat-1\"}"
```
