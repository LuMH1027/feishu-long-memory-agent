# 飞书机器人配置与方向B验证指南

本文档说明如何把飞书机器人接入当前项目，并验证方向B“飞书项目决策与上下文记忆”是否真正生效。

当前项目采用双通道方案：

1. **飞书服务端 SDK 长连接**：接收群消息事件，不需要公网回调地址，适合本地开发和演示。
2. **飞书官方 Python SDK**：把后端生成的回复文本发送回飞书群。

代码链路：

```text
飞书群消息
-> lark-oapi SDK 长连接
-> feishu_bot/sdk_events.py
-> POST /api/v1/feishu/message/analyze
-> backend/routers/feishu.py
-> memories / decision_memories 数据库表
-> 可选：SDK 自动回复群消息
```

## 1. 飞书开放平台配置

### 1.1 创建企业自建应用

进入飞书开放平台，创建一个企业自建应用。

需要记录以下信息：

```text
App ID
App Secret
Verification Token
Encrypt Key
```

这些值后面会写入 `.env`。

### 1.2 开启机器人能力

在应用能力中开启机器人能力，并把机器人添加到需要测试的飞书群。

### 1.3 开通权限

至少需要开通以下能力：

```text
接收群聊消息事件
读取消息内容
发送消息到群
```

如果飞书后台要求具体权限名，以开放平台页面展示为准。开通后通常需要发布应用版本，或在测试企业内启用。

### 1.4 配置事件订阅

当前项目优先使用 SDK 长连接接收事件，本地开发时不需要配置公网 Request URL。

你仍然需要在飞书后台的事件订阅中启用消息事件，例如：

```text
im.message.receive_v1
```

如果你后续要使用 HTTP 回调模式，则配置：

```text
https://你的公网域名/api/v1/feishu/event/callback
```

本地 `127.0.0.1` 无法直接给飞书后台访问，HTTP 回调需要 ngrok、cloudflared 或服务器公网域名。

## 2. 本项目环境配置

### 2.1 安装依赖

当前项目使用 `lark-oapi` 接收飞书事件。你的环境里如果还没有安装，需要执行：

```powershell
pip install lark-oapi==1.5.5
```

如果你希望按项目依赖统一安装：

```powershell
pip install -e .
```

### 2.2 配置 `.env`

在项目根目录 `.env` 中加入：

```env
FEISHU_APP_ID=你的 App ID
FEISHU_APP_SECRET=你的 App Secret
FEISHU_VERIFICATION_TOKEN=你的 Verification Token
FEISHU_ENCRYPT_KEY=你的 Encrypt Key

MEM_AGENT_BACKEND_URL=http://127.0.0.1:8000
FEISHU_SDK_LOG_LEVEL=INFO
```

如果只验证“群消息能不能更新数据库”，以上配置就够了。

如果还要让机器人自动回复群消息，继续配置：

```env
FEISHU_AUTO_REPLY=true
```

### 2.3 配置 SDK 自动回复

当前代码用飞书官方 Python SDK 发送群消息，调用位置在：

```text
feishu_bot/sdk_messages.py
```

发送链路是：

```text
backend/routers/feishu.py
-> feishu_bot/sdk_messages.py
-> lark_oapi Client.im.v1.message.create()
```

使用前需要确认：

1. 已安装 `lark-oapi`。
2. `.env` 中已配置 `FEISHU_APP_ID` 和 `FEISHU_APP_SECRET`。
3. 飞书应用具备发送群消息权限。

如果 SDK 发送失败，数据库更新仍然可用，只是自动回群会失败并返回结构化错误。

## 3. 启动项目

需要开两个终端。

### 3.1 终端一：启动后端 API

```powershell
uvicorn backend.main:app --host 127.0.0.1 --port 8000
```

验证后端是否正常：

```powershell
curl http://127.0.0.1:8000/health
```

预期返回：

```json
{"status":"ok","message":"记忆引擎服务运行正常"}
```

### 3.2 终端二：启动飞书 SDK 事件订阅

```powershell
python scripts\run_feishu_sdk_events.py
```

这个进程会通过飞书 SDK 长连接监听群消息，然后转发到：

```text
POST /api/v1/feishu/message/analyze
```

## 4. 群里如何交互

### 4.1 决策类消息：更新数据库

在飞书群里发送：

```text
@机器人 不对，project-a 以后统一用 prod 部署，不再使用 staging
```

预期效果：

1. SDK 收到群消息。
2. 后端识别这是决策消息。
3. 写入 `memories` 表，类型为 `project_decision`。
4. 如果使用真实数据库，也会写入 `decision_memories` 表。
5. 如果 `FEISHU_AUTO_REPLY=true` 且 SDK 发送权限正常，机器人会回复：

```text
已记录团队决策：不对，project-a 以后统一用 prod 部署，不再使用 staging
```

### 4.2 查询类消息：检索历史记忆

先确保数据库里已有 CLI 命令，例如：

```powershell
curl -X POST "http://127.0.0.1:8000/api/v1/cli/command/record" `
  -H "Content-Type: application/json" `
  -d "{\"command\":\"kubectl apply -f k8s/prod.yaml\",\"count\":2,\"shell\":\"powershell\",\"directory\":\"E:/workspace/project-a\"}"
```

然后在飞书群里问：

```text
@机器人 project-a 怎么部署？
```

预期效果：

1. 后端识别这是查询类消息。
2. 检索 `memories` 中的 CLI 命令、工作流、项目决策。
3. 如果开启自动回复，机器人把结果发回群里。

### 4.3 决策影响 CLI 推荐

当群里已经记录：

```text
project-a 以后统一用 prod 部署，不再使用 staging
```

再调用 CLI 推荐接口：

```powershell
curl -X POST "http://127.0.0.1:8000/api/v1/cli/command/suggest" `
  -H "Content-Type: application/json" `
  -d "{\"partial_command\":\"kubectl apply\",\"directory\":\"E:/workspace/project-a\"}"
```

预期效果：

```text
kubectl apply -f k8s/prod.yaml
```

会排在：

```text
kubectl apply -f k8s/staging.yaml
```

前面，即使 staging 历史使用次数更高。

## 5. 不接飞书时如何本地验证

如果你还没有配置飞书应用，可以直接请求后端模拟群消息。

### 5.1 模拟决策入库

```powershell
curl -X POST "http://127.0.0.1:8000/api/v1/feishu/message/analyze" `
  -H "Content-Type: application/json" `
  -d "{\"content\":\"不对，project-a 以后统一用 prod 部署，不再使用 staging\",\"chat_id\":\"chat-test\",\"user_id\":\"lead-1\",\"mentioned\":true}"
```

预期返回：

```json
{
  "action": "decision_stored"
}
```

### 5.2 模拟飞书查询

```powershell
curl -X POST "http://127.0.0.1:8000/api/v1/feishu/message/analyze" `
  -H "Content-Type: application/json" `
  -d "{\"content\":\"project-a 怎么部署？\",\"chat_id\":\"chat-test\",\"mentioned\":true}"
```

预期返回：

```json
{
  "action": "suggest_cards",
  "should_push": true,
  "cards": []
}
```

如果 `cards` 不为空，说明命中了历史记忆。

## 6. 如何查看数据库是否更新

### 6.1 通过 API 查看

```powershell
curl "http://127.0.0.1:8000/api/v1/memory/list?limit=20"
```

重点看：

```json
{
  "type": "project_decision",
  "source": "feishu_group",
  "metadata": {
    "project": "project-a",
    "preferred_terms": ["prod"],
    "rejected_terms": ["staging"],
    "status": "active"
  }
}
```

### 6.2 通过 SQLite 查看

如果你的 `DATABASE_URL` 使用的是默认 SQLite，可以直接查表：

```powershell
python -c "import sqlite3, json; conn=sqlite3.connect('db/memory.db'); rows=conn.execute('select id,type,source,content,memory_metadata from memories order by created_at desc limit 10').fetchall(); [print(row) for row in rows]"
```

查看决策表：

```powershell
python -c "import sqlite3; conn=sqlite3.connect('db/memory.db'); rows=conn.execute('select id,topic,conclusion,reason from decision_memories order by rowid desc limit 10').fetchall(); [print(row) for row in rows]"
```

## 7. 当前代码中各部分关系

| 功能 | 代码位置 | 说明 |
| --- | --- | --- |
| SDK 长连接接收事件 | `feishu_bot/sdk_events.py` | 使用 `lark_oapi` 接收飞书消息 |
| 启动 SDK 事件订阅 | `scripts/run_feishu_sdk_events.py` | 单独进程启动 |
| 飞书消息分析 | `backend/routers/feishu.py` | 判断是决策入库还是查询 |
| 决策写入数据库 | `backend/routers/feishu.py` + `backend/routers/memory.py` | 写入 `memories`，并可同步 `decision_memories` |
| 自动回复群消息 | `feishu_bot/sdk_messages.py` | 调用飞书 SDK 发送文本 |
| CLI 推荐重排 | `backend/routers/cli.py` | 读取 `project_decision` 干预命令排序 |

## 8. 常见问题

### 8.1 运行 SDK 订阅时报错：未安装 lark-oapi

执行：

```powershell
pip install lark-oapi==1.5.5
```

### 8.2 群里发消息后数据库没有变化

按顺序检查：

1. `uvicorn` 后端是否正在运行。
2. `python scripts\run_feishu_sdk_events.py` 是否正在运行。
3. `.env` 是否有 `FEISHU_APP_ID` 和 `FEISHU_APP_SECRET`。
4. 飞书应用是否开启消息事件订阅。
5. 机器人是否已经加入目标群。
6. 应用权限是否已发布或启用。

### 8.3 数据库更新了，但群里没有回复

检查：

1. `.env` 是否设置 `FEISHU_AUTO_REPLY=true`。
2. 是否安装 `lark-oapi`。
3. `.env` 是否配置 `FEISHU_APP_ID` 和 `FEISHU_APP_SECRET`。
4. 飞书应用是否具备发送群消息权限。

### 8.4 不想自动回复，只想验证入库

设置：

```env
FEISHU_AUTO_REPLY=false
```

或者直接删除该环境变量。

此时群消息仍然可以进入后端并更新数据库，只是不会发消息回群。

## 9. 推荐验证顺序

建议按下面顺序验证，最容易定位问题：

1. `pytest tests\unit\test_memory_and_feishu_routes.py -q -p no:cacheprovider`
2. 启动后端并访问 `/health`
3. 用 `/api/v1/feishu/message/analyze` 本地模拟决策入库
4. 用 `/api/v1/memory/list` 确认数据库有 `project_decision`
5. 启动 `python scripts\run_feishu_sdk_events.py`
6. 在飞书群里发送决策消息
7. 再次查看 `/api/v1/memory/list`
8. 配置 SDK 自动回复和 `FEISHU_AUTO_REPLY=true`
9. 在群里发送查询消息，确认机器人自动回复
