# 2. 记忆提取与结构化落地（决策入库）

## 目标
实现在飞书沟通环境里利用 LLM 自动汲取有效团队决策及项目限定条件。

## 涉及文件
- `backend/routers/feishu.py`
- `core/retriever.py`
- `core/storage.py`

## 开发完成标准
- 当识别到“决定”、“以后统一用”、“放弃”、“不对/更正”等纠正语意时，通过 LLM API 解析出结构化决策记录（决策事件、提出理由、落地结论、关联项目主体）。
- **矛盾更新与长期记忆治理机制**：将该类结构化事实存入关系表，并在 ChromaDB 中保存向量特征用于后续打分判定。若检测到针对同一配置/项目的历史冲突决策（例如旧有方案A、现决议方案B），自动将旧记忆标记为 `inactive`，用新记忆覆盖，有效降低过期记忆与脏数据污染。

## 测试用例思路

## 2026-04-29 实现记录

本阶段已完成飞书项目决策的结构化抽取与入库：

1. 新增 `POST /api/v1/feishu/decision/extract`。
2. 新增决策语义识别：`决定`、`确认`、`统一`、`以后`、`不再`、`废弃`、`改成`、`更正`、`不对`、`采用` 等。
3. 决策会写入统一 `memories` 表，类型为 `project_decision`，来源为 `feishu_group`。
4. 当使用真实数据库时，同步写入 `decision_memories` 表，保留 `topic`、`conclusion`、`reason`、`related_persons` 等结构化字段。
5. 元数据中会保存：
   - `topic_key`：用于同主题覆盖。
   - `project`：如 `project-a`。
   - `preferred_terms`：如 `prod`。
   - `rejected_terms`：如 `staging`。
   - `chat_id` / `message_id` / `extracted_at`。
6. 复用已有矛盾更新机制，新决策可将旧决策标记为 `inactive`，避免过期团队规则污染后续检索和推荐。

接口示例：

```bash
curl -X POST "http://localhost:8000/api/v1/feishu/decision/extract" ^
  -H "Content-Type: application/json" ^
  -d "{\"content\":\"不对，project-a 以后统一用 prod 部署，不再使用 staging\",\"chat_id\":\"chat-1\",\"user_id\":\"lead-1\"}"
```
