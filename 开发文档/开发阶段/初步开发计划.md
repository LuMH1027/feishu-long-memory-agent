# 企业级记忆引擎项目初步开发计划

## 一、需求理解
### 目标阐述
本次开发目标是构建一套面向企业办公场景的**可落地记忆引擎系统**，解决大模型"失忆"痛点，实现记忆的完整生命周期管理（提取→存储→检索→更新→遗忘），并在CLI终端与飞书生态中无缝流转，最终通过量化评测证明其实际效能。
### 系统关联分析
- 对接飞书开放平台：读取飞书群聊、文档、日程等数据，推送记忆提醒卡片
- 对接OpenClaw CLI：监听终端命令输入，提供上下文感知的命令补全与建议
- 现有系统边界：作为独立中间层服务，不侵入现有业务系统，通过API/SDK方式对接

## 三、详细实施步骤
### 阶段1：架构设计与场景定义（2天）
1. **场景选型**：优先选择「方向A：CLI高频命令记忆 + 方向B：飞书项目决策记忆」组合，兼顾开发者与项目管理场景，演示效果直观
2. **数据模型设计**：
   - 关系型数据库表（SQLite/PostgreSQL）：
     ```sql
     -- 记忆主表
     CREATE TABLE memories (
       id VARCHAR(32) PRIMARY KEY,
       content TEXT NOT NULL,
       type VARCHAR(20) NOT NULL, -- cli_command / project_decision / user_preference
       source VARCHAR(20) NOT NULL, -- cli / feishu_group / feishu_doc
       user_id VARCHAR(64),
       team_id VARCHAR(64),
       created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
       updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
       expire_at TIMESTAMP,
       hit_count INT DEFAULT 0
     );
     
     -- 决策记忆扩展表
     CREATE TABLE decision_memories (
       id VARCHAR(32) PRIMARY KEY REFERENCES memories(id),
       topic TEXT NOT NULL,
       conclusion TEXT NOT NULL,
       reason TEXT,
       related_persons TEXT,
       deadline TIMESTAMP
     );
     ```
   - 向量库：使用Chroma/FAISS存储记忆内容的embedding向量，用于语义检索
3. **数据流设计**：输入→记忆提取→向量编码→双库存储→检索触发→结果排序→输出推送

### 阶段2：基础开发环境搭建（1天）
1. 初始化项目结构：
   ```
   feishu-long-memory-agent/
   ├── backend/          # FastAPI后端服务
   ├── cli/              # CLI客户端
   ├── feishu_bot/       # 飞书机器人服务
   ├── core/             # 记忆引擎核心模块
   ├── db/               # 数据库操作与迁移脚本
   ├── tests/            # 测试用例集
   └── docs/             # 文档交付物
   ```
2. 依赖安装：
   - 核心依赖：`fastapi uvicorn sqlalchemy chromadb openai langchain feishu-python-sdk typer python-multipart`
3. 飞书机器人基础配置：申请企业自建应用权限，开通群聊消息接收、消息发送权限

### 阶段3：记忆引擎核心模块开发（3天）
1. **记忆提取模块**（`core/extractor.py`）：
   - CLI命令提取：监听终端输入，自动识别命令、参数、路径上下文
   - 飞书决策提取：调用LLM从群聊/文档中识别决策主题、结论、相关人、截止日期
   - 支持用户主动记忆注入：命令 `/memorize 内容` 主动添加记忆
2. **记忆存储模块**（`core/storage.py`）：
   - 双写逻辑：结构化信息写入关系库，内容embedding写入向量库
   - 自动过期策略：根据记忆类型设置默认过期时间
3. **记忆检索模块**（`core/retriever.py`）：
   - 混合检索：关键词匹配 + 语义相似度匹配 + 时间权重 + 命中次数权重
   - 上下文感知：自动识别当前场景（CLI/飞书群/文档）过滤相关记忆
4. **记忆更新与遗忘模块**（`core/updater.py`）：
   - 冲突检测：相同主题新记忆自动覆盖旧记忆，保留版本历史
   - 遗忘策略：基于艾宾浩斯曲线，低访问频率记忆自动下沉或归档

### 阶段4：端侧对接开发（2天）
1. **CLI端对接**：
   - 开发命令补全钩子，用户输入命令前缀时自动调用检索接口返回推荐结果
   - 支持命令 `mem list` 查看历史记忆，`mem clear` 清空个人记忆
2. **飞书端对接**：
   - 接收群聊@消息、文档评论事件，自动提取记忆
   - 实现主动推送逻辑：当群聊讨论触及历史决策话题时，自动推送历史决策卡片
3. **API接口开发**：
   ```
   POST /api/v1/memory/extract  # 提取并存储记忆
   GET /api/v1/memory/retrieve  # 检索相关记忆
   PUT /api/v1/memory/update    # 更新记忆内容
   DELETE /api/v1/memory/{id}   # 删除记忆
   ```

### 阶段5：测试与评测验证（2天）
1. 强制评测项测试：
   - 抗干扰测试：注入100条无关记忆后，验证1周前关键记忆检索准确率≥95%
   - 矛盾更新测试：先后注入冲突指令，验证系统正确识别时序、优先返回最新记忆
   - 效能测试：对比使用前后操作步数/输入字符数，提效≥60%
2. 边界case测试：多人共享记忆冲突、超长文本记忆、过期记忆自动清理等

### 阶段6：交付物准备（1天）
1. 架构白皮书：包含场景定义、数据流图、价值论证
2. Demo录制：CLI端命令补全演示、飞书端决策记忆推送演示
3. 评测报告：完整测试用例集、量化数据对比、效能分析

## 四、技术建议
| 技术选型       | 推荐方案                | 优势说明                                                                 |
|----------------|-------------------------|--------------------------------------------------------------------------|
| 后端框架       | FastAPI                 | 轻量高效、自动生成API文档、异步支持，适合快速开发Demo                    |
| 向量库         | Chroma                  | 纯Python实现、无需额外部署、本地存储，适合小型比赛项目                    |
| LLM对接        | OpenAI GPT-3.5/文心一言 | 语义理解能力强，适合记忆提取、冲突检测场景，支持本地模型替换              |
| CLI开发        | Typer                   | 类型提示驱动、自动生成帮助文档、开发效率高                                |
| 飞书对接       | 官方Python SDK          | 封装了所有开放平台API，避免重复造轮子                                      |
| 部署方式       | Docker Compose          | 一键启动所有服务，方便评委快速部署验证Demo                                |

> 所有技术选型均匹配现有技术栈，无额外学习成本，可快速实现最小可行产品。

## 六、风险提醒
1. **飞书API权限风险**：部分高级接口需要企业管理员审批，提前确认权限范围，避免开发完成后无法上线
2. **向量检索准确率风险**：embedding模型选择和检索阈值设置直接影响结果准确率，需要多轮测试调整参数
3. **冲突处理边界风险**：多用户注入相似记忆、时序冲突等场景容易出现逻辑漏洞，需要覆盖全面的测试用例
4. **性能瓶颈风险**：记忆量级超过1万条后检索速度可能变慢，提前设计分页、缓存机制
5. **评测指标设计风险**：效能指标需要足够客观可量化，避免主观描述导致评委认可度低

> 基于以下假设制定本计划：项目开发周期为11天，团队规模3-4人，具备Python开发基础和飞书开放平台使用经验。如果实际情况不同可灵活调整各阶段时间分配。
