# 企业级记忆引擎 - 使用说明手册

> 写给完全不懂技术的你：这份文档将用最简单的语言，告诉你这个工具是什么、能帮你解决什么问题、以及如何使用它。

---

## 一、这个工具是什么？

### 一句话解释

**企业级记忆引擎**就像一个"团队的外置大脑"，它能帮你记住那些容易忘记的重要信息——无论是你用过的命令，还是团队在群里讨论过的决策。

### 生活中的类比

想象一下这些场景：

| 场景 | 没有记忆引擎 | 有了记忆引擎 |
|------|-------------|-------------|
| 你上周用过一个很复杂的命令 | 翻遍笔记找不到，只能重新百度 | 输入几个关键词就能找到 |
| 团队上周定了一个重要的决定 | 一周后没人记得，又要重新讨论 | 问一下机器人就能得到答案 |
| 新同事入职不知道项目规范 | 要一个个问老员工 | 直接查历史决策记录 |

**简单来说：它帮你把"脑子里的知识"变成"随时可以查到的资料"。**

## 二、它能帮你解决什么问题？

### 问题1：开发者经常忘记命令

作为程序员，你可能遇到过这些烦恼：

- 上周写过一个很长的 Docker 命令，今天又要用，但是死活想不起来
- 有个部署命令偶尔才用一次，每次都要翻文档
- 团队规定用某个命令，但你总是记不住参数

**记忆引擎的解决方案：**
- 把命令存起来，下次用关键词就能搜到
- 用得越多的命令，排在越前面
- 团队规范的命令会自动推荐

### 问题2：团队决策容易被遗忘

作为团队成员，你可能遇到过这些烦恼：

- 上周群里讨论定下的方案，这周又有人问"我们用哪个？"
- 新来的同事不知道项目之前做过哪些重要决定
- 有时候自己都不记得当初为什么这么做

**记忆引擎的解决方案：**
- 自动识别群聊里的"决定性"消息并保存
- 有人问相关问题时，自动提醒历史决策
- 记录决策的原因，方便以后回顾

### 问题3：知识分散在不同地方

- 命令在终端历史里
- 决策在飞书群聊里
- 文档在各种笔记软件里

**记忆引擎的解决方案：**
- 统一收集、统一存储、统一查询
- 一个地方就能找到所有相关信息

## 四、如何使用这个工具？

### 第一步：安装（需要技术人员帮忙）

> 这部分需要技术人员操作，你只需要告诉他们你想用这个工具。

技术人员需要做以下事情：

1. 下载代码
2. 安装依赖
3. 启动服务

安装完成后，你就可以开始使用了。

### 第二步：在电脑上使用（程序员日常）

#### 功能1：记住一个命令

当你有一个复杂的命令想要保存时：

```bash
mem memorize "docker run -p 8080:80 my-app:latest" --type "docker命令"
```

**效果：**
```
✅ 记忆已保存，ID: abc123
```

#### 功能2：搜索命令

当你忘记命令时，用自然语言搜索：

```bash
mem search "启动docker容器"
```

**效果：**
```
找到以下相关命令：

1. docker run -p 8080:80 my-app:latest
   描述：docker命令
   使用次数：5

请选择要执行/复制的命令序号（输入0退出）：
```

#### 功能3：查看所有记忆

```bash
mem list
```

**效果：**
```
[abc123] [docker命令] docker run -p 8080:80 my-app:latest...
[def456] [周报命令] python send_weekly.py --to team...
[ghi789] [项目决策] v2.0使用新支付接口...
```

#### 功能4：自动记录高频命令

```bash
mem watch
```

**效果：**
```
✅ 已扫描历史命令，自动记录了15条高频命令
```

这个功能会自动扫描你之前用过的命令，把经常用的都记录下来。

#### 功能5：保存工作流程

如果你有一组命令经常一起执行，可以保存为工作流：

```bash
mem workflow save "部署项目" "git pull" "docker build -t my-app ." "docker push my-app"
```

下次执行时：

```bash
mem workflow run "部署项目"
```

**效果：**
```
🚀 开始执行工作流《部署项目》，共3个步骤

步骤 1/3: git pull
是否执行？[Y/n]: Y
✅ 执行成功

步骤 2/3: docker build -t my-app .
是否执行？[Y/n]: Y
✅ 执行成功

步骤 3/3: docker push my-app
是否执行？[Y/n]: Y
✅ 执行成功
```

### 第三步：在飞书群里使用（团队协作）

#### 功能1：记录团队决策

在飞书群里，当有人做出决定时，机器人会自动识别并记录。

**示例对话：**

```
产品经理：@所有人 以后项目统一用 prod 环境部署，不再使用 staging
记忆机器人：✅ 已记录团队决策：以后项目统一用 prod 环境部署
```

机器人会自动识别这些关键词：
- "决定"、"确认"、"统一"
- "以后"、"不再"、"废弃"
- "改成"、"更正"

#### 功能2：查询历史决策

当有人问到相关问题时，机器人会自动提醒。

**示例对话：**

```
新同事：我们部署用什么环境来着？
记忆机器人：📋 历史决策提醒
            主题：部署环境选择
            结论：以后项目统一用 prod 环境部署
            废弃方案：staging
            记录时间：2024-05-01
```

#### 功能3：查询历史命令

机器人还能帮你查询团队之前用过的命令。

**示例对话：**

```
同事：怎么重启服务器？
记忆机器人：💻 历史命令推荐
            命令：systemctl restart nginx
            使用次数：12次
            成功率：100%
```

## 六、常见问题解答

### Q1：我需要懂技术才能用吗？

**不需要！** 

- 如果你是程序员，只需要记住几个简单的命令（`mem search`、`mem list`）
- 如果你是普通用户，只需要在飞书群里正常聊天，机器人会自动工作

### Q2：我的数据安全吗？

**安全！**

- 数据存储在你自己的服务器上，不会上传到外部
- 只有你的团队成员能访问
- 你可以随时删除所有数据

### Q3：需要付费吗？

**不需要！**

- 这是一个开源项目，完全免费
- 你只需要准备一台服务器（或者用自己的电脑）

### Q4：能记住多少东西？

**理论上无限制！**

- 存储容量取决于你的服务器硬盘
- 搜索速度会随着数据量增加而变慢，但正常使用完全没问题

### Q5：如果机器人记错了怎么办？

**可以纠正！**

在飞书群里说：
```
不对，以后周报发给B，不再发给A
```

机器人会自动更新记录，并标记旧记录为"已废弃"。

## 七、使用技巧

### 技巧1：给命令打标签

保存命令时，加上类型标签，方便以后搜索：

```bash
mem memorize "npm run build" --type "构建命令"
mem memorize "git push origin main" --type "git命令"
```

### 技巧2：用自然语言搜索

不用记住完整命令，用描述性的词语搜索：

```bash
mem search "构建项目"
mem search "推送代码"
mem search "重启服务"
```

### 技巧3：让机器人自动学习

运行 `mem watch` 命令，让机器人自动扫描你的历史命令：

```bash
mem watch
```

它会自动识别你经常用的命令并保存。

### 技巧4：在群里明确表达决策

让机器人更容易识别你的决策：

```
✅ 好的表达方式：
"以后我们统一用 prod 环境"
"决定采用方案A"
"确认截止日期是5月10日"

❌ 不好的表达方式：
"我觉得可能用 prod 比较好？"
"要不试试方案A？"
```
