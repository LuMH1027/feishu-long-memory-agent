# 方向B：飞书决策与团队协同记忆开发详细指南

## 一、功能总览与目标
### 1.1 核心目标
构建一个建立在统一长期记忆底座之上的协作中枢，实现开发者 CLI 操作经验与飞书团队讨论决策的无缝流转：
- **沉淀飞书群聊中的架构讨论与决策**（"为什么这么做"），作为团队长期记忆。
- **联动 CLI 记忆**（"具体怎么做"），当飞书群出现对应场景的讨论时，主动推送历史的高频、高质量 CLI 指令。
- **支持在飞书中快捷消费 CLI 沉淀的操作手册与工作流**（通过记忆流转）。
- **飞书中达成的项目变动决策可反向覆盖或影响 CLI 的命令推荐权重**。

### 1.2 适用场景
- **经验共享**：新人或成员在飞书群提问某项具体配置、部署、测试怎么启动时，机器人从 CLI 记忆库自动检索并推送高精准操作命令。
- **项目决策追溯**：讨论当前任务为什么采用 A 方案而不采用 B 方案时，自动关联过往的讨论上下文记录。
- **工作流沉淀与执行**：开发者通过 CLI 记录的 `workflow`（如 docker 清理流程），团队成员只需在飞书 @机器人即可一键获取。飞书卡片可支持一键复制，或交由 OpenClaw 执行完后将结果回写记忆库。
- **动态修正**：飞书项目决策发生改变时（例如：废弃 staging 统一用 prod），CLI 工作流与高频命令预测跟随决策变化自动更新推荐权重。

## 二、架构设计与双向联动机制

方向 B 与 方向 A 是紧密互补的两个轮子，在技术栈上统一基于 **FastAPI (后端) + Typer (CLI) + SQLite (关系型数据) + ChromaDB (向量库) + 飞书 OpenAPI** 构建：

**1. 统一后台与数据底座及元数据解析：**
底层使用 SQLite + ChromaDB 架构作为统一数据存取层。
通过 `memories` 相关表结构同时收口 CLI 高频命令和 `decision_memories` (飞书项目决策)，形成知识关联网络。
针对命令记忆，提取并解析丰富的上下文元数据（`directory`, `command_pattern`, `execution_feedback`），深度拆解 program、subcommand、flags 与 paths，让飞书群聊中的泛化决策能够精准匹配并干预特定项目目录下的具体命令。

**2. CLI -> 飞书 的知识上行：**
- 开发者在终端执行高频命令/工作流 `->` 被动/主动记录入库。
- 飞书侧出现问询 `@机器人 启动 webapp 容器怎么做？` `->` 触发 `GET /api/v1/memory/search`。
- 飞书机器人推送包含项目目录、历史使用次数和成功率的历史命令卡片 `->` 极大提升团队知识沉淀并引导操作。

**3. 飞书 -> CLI 的知识下行：**
- 飞书群产出业务决策（如“弃用 staging 采用 prod 部署”） `->` `POST /api/v1/memory/extract` 提取决策入库。
- 开发者在本地环境使用 CLI 或键入前缀 `->` `POST /api/v1/cli/command/suggest`。
- 引擎检索时动态分析决策，置顶受新决策推崇的命令，将已淘汰的环境命令做降权处理。

## 三、分阶段开发与测试指南（按顺序执行）

### 阶段1：飞书查询卡片与跨库联动构建
**目标**：打破数据孤岛，使得飞书侧能够查询解析并展现 CLI 侧的资产记忆。
**涉及文件**：`backend/routers/feishu.py`, `backend/routers/memory.py`
**开发完成标准**：
- 完成飞书 webhook 中的查询意图识别。
- 定义“历史 CLI 命令卡片”和“工作流执行卡片”模板（如返回带复制交互和步骤细项的交互式响应形式）。
- 通过飞书的指令查询或自然语言 `@` 能顺利拉取包含目标上下文的指令。

**测试用例思路**：
```bash
# 模拟向 API 后端发起带项目上下文意图的查询
curl -X GET "http://localhost:8000/api/v1/memory/search?query=启动webapp容器"
# 预期可调取 CLI 侧记录的容器启动指令与历史成功率，并以卡片 JSON 结构反馈。
```

### 阶段2：记忆提取与结构化落地（决策入库）
**目标**：实现在飞书沟通环境里利用 LLM 自动汲取有效团队决策及项目限定条件。
**涉及文件**：`backend/routers/feishu.py`, `core/retriever.py`
**开发完成标准**：
- 当识别到“决定”、“以后统一用”、“放弃”、“不对/更正”等纠正语意时，通过 LLM API 解析出结构化决策记录（决策事件、提出理由、落地结论、关联项目主体）。
- **矛盾更新与长期记忆治理机制**：将该类结构化事实存入关系表，并在 ChromaDB 中保存向量特征用于后续打分判定。若检测到针对同一配置/项目的历史冲突决策（例如旧有方案A、现决议方案B），自动将旧记忆标记为 `inactive`，用新记忆覆盖，有效降低过期记忆与脏数据污染。

**测试用例思路**：
```bash
# @机器人 我们以后统一用 prod 命名空间部署 project-a，不再使用 staging 了。
# 验证：检查对应 vector store 里是否已落库包含 namespace 设定的偏好类记忆记录。
```

### 阶段3：检索关联与主动推送策略（基于话题触发）
**目标**：探索隐性体验优化，不被 @ 仍能在关键时刻抛出有价值信息。
**涉及文件**：`feishu_bot/`相关事件模块, `backend/routers/feishu.py`
**开发完成标准**：
- 对飞书群组的消息长尾流增加监听和摘要分析。
- 当出现如 `部署 webapp`, `重启 api-server`, `备份订单库` 的话题时，调用关联检索。
- 若命中高度相关（Score 达标）的具体 CLI 指令历史或决策，推送“历史讨论摘要或推荐操作”。

### 阶段4：统一权重体系（决策干预 CLI 推荐）
**目标**：实现闭环流转的最点睛之笔，用高维度团队决策约束个人终端命令环境下的提示候选。
**涉及文件**：`backend/routers/cli.py`, `core/retriever.py`
**开发完成标准**：
- 升级 `search` 与 `suggest` 接口中的检索重排链路，构建 **向量检索 + 关键词兜底 + CLI 专用混合重排** 机制。首先统筹命令前缀、使用频率、最近使用时间、项目目录上下文与执行成功率（利用 `directory` 与 `execution_feedback` 元数据）进行初始评估。
- **团队决策动态重排机制**：如果 CLI 中命令文本所涉及的 `flags`、`paths` 等关键参数被最新入库的飞书决策判定为过期/负向评价（例如旧有的 staging 环境命令），大幅降低其推荐评分。
- 反向提升命中最新规范属性（如 `prod` 命令）操作的召回排名。

## 四、自证评测与答辩演示链路 (Test & Prove)

在最终产品答辩中，应将 A、B 双向打通作为核心亮点展演，推荐设计如下一镜到底流：

1. **起点（本地沉淀阶段）：** 开发人员通过终端正常保存清理策略工作流：
   `mem workflow save "docker清理" "docker system prune -f" "docker volume prune -f"`
2. **连接点（查缺补漏与共享）：** 运维新同事在飞书业务群输入：`@机器人 docker 清理流程该怎么配？` 机器人精准应答并展示完整的工作流卡片。
3. **闭环点（团队决议逆推）：** 技术负责人见状在群里补充强调：`@机器人 团队规范强调一下，清理机器不能再加 -f 强制处理，必须带特定安全参数。` 系统回复已收录该更新规则。
4. **终点（规范约束效验）：** 当开发者再次在终端输入 CLI `mem search "docker清理"` 时，提示卡片将依照团队最近决议返回经过修正（或带风险警示）的命令优先级，把旧版不规范命令踢出前列并展示替代方案。

> **答辩话术提示**：
> "我们并没有把 CLI 和飞书做成两个孤立的功能模块，而是将它们视为了同一大背景下的两个端。一个偏向沉淀开发者『具体怎么做』的本地习惯经验，一个偏向收口整个团队『为什么这么做』的沟通决策。通过这个统一的长期记忆底座做连线，完成了从组织决策到落操落地的完美工作流融合。这真正体现了企业级记忆引擎的协同价值。"

### 4.2 工程验证与效能评测 (Benchmark & Metrics)

需要证明系统不仅“能记住”，而且“提效显著”：
基于 **pytest** 框架，为记忆管理逻辑（`memories` 录入、覆盖与检索）构建完整的**单元测试**与**集成测试**，同时构建单独的 `evaluation` 评测套件，通过以下核心策略量化业务价值：
- **检索鲁棒性测试**：设计包含干扰对话和相似词意的高难度评测集，量化输出 **Hit@1 / Hit@3 / MRR (Mean Reciprocal Rank)** 核心指标。
- **矛盾更新与一致性检验**：测试当用户输入“不对，换成X方案”、“以后统一用Y脚本”时，系统是否能按预期将旧历史标为 `inactive`，有效拦截脏数据污染。
- **效率提升量化验证（ROI自证）**：统计在接入此引擎以后，处理长路径或多参数运维任务时，所削减的**击键字符数**以及节约的任务**平均流转耗时/操作步数**。
