# 企业级记忆引擎 - 录屏脚本

> 总时长：~12 分钟 | 分 4 个 Part
>
> - Part 1：CLI 方向（~4 分钟）— 自动 + 手动
> - Part 2：飞书 API 方向（~3 分钟）— 全自动
> - Part 3：飞书群聊真实交互（~4 分钟）— 全手动
> - Part 4：系统监控 & 收尾（~1 分钟）— 手动

---

## 录屏前准备（不要录进去）

### 终端布局

开 **3 个终端窗口**，水平排列：

| 位置 | 窗口 | 用途 | 何时启动 |
|------|------|------|---------|
| 左 | 终端 1 | 后端服务 | 立即 |
| 中 | 终端 2 | 自动化脚本 + CLI 操作 | 配置 CLI 后 |
| 右 | 终端 3 | 飞书机器人监听 | Part 3 开始时 |

### 启动步骤

**终端 2（先配置 CLI，再启动后端）：**

```powershell
cd e:\feishu-long-memory-agent

# 第一步：配置 CLI（不需要后端运行）
python -m cli.main configure
# 输入: http://127.0.0.1:8000/api/v1
# 按回车

# 第二步：清空数据库（必须在后端启动前执行，否则数据库被占用）
python 交付物/demo_record.py --reset-db
# 等它跑到第一个暂停点后，再去启动后端
```

**终端 1（后端，等终端 2 跑起来后再启动）：**

```powershell
cd e:\feishu-long-memory-agent
python -m uvicorn backend.main:app --host 127.0.0.1 --port 8000
```

等看到 `Application startup complete.`，然后切回终端 2 继续操作。

| 项目 | 建议 |
|------|------|
| 录屏软件 | OBS Studio |
| 分辨率 | 1920x1080 |

| 浏览器 | `http://127.0.0.1:8000/docs` 缩放 125% |

## Part 1：CLI 记忆引擎（面向开发者）

> 时长 ~4 分钟 | 展示：存命令、搜命令、矛盾更新、工作流

---

### 步骤 0：启动自动脚本（15 秒）

> 脚本已在准备阶段启动，此时终端 2 应该已经跑到第一个暂停点。
> 如果还没启动，在终端 2 输入：
> ```powershell
> python 交付物/demo_record.py --reset-db
> ```
> **注意**：必须在后端启动前执行 `--reset-db`，否则数据库被占用会报错。

脚本开始自动执行 CLI 记忆注入。

> **字幕**：把常用的长命令存进记忆系统，以后再也不用手打了。

脚本会自动注入 4 条命令，等它跑完并暂停。

---

### 👆 步骤 1：语义搜索（50 秒）⭐ 核心亮点

> 脚本暂停，提示你手动操作

**在终端 2 输入：**

```powershell
python -m cli.main search "启动webapp容器"
```

按回车。停 2 秒。

> **字幕**：我没打 docker，没打 run，只说了「启动 webapp 容器」—— AI 语义检索，懂你的意思。

**再输入：**

```powershell
python -m cli.main search "查看生产环境api日志"
```

按回车。停 2 秒。

> **字幕**：换个说法也能找到。不用记参数，不用翻文档。

**操作完成后，按回车继续自动演示。**

---

### 步骤 2：前缀推荐（20 秒，自动）

脚本自动运行 `suggest docker` 和 `suggest kubectl`。

> **字幕**：输入命令前缀，智能排序推荐。比 Tab 补全更聪明 —— 它知道你最常用哪个。

---

### 👆 步骤 3：矛盾更新（50 秒）⭐ 核心亮点

> 脚本暂停，提示你手动操作

**输入旧记忆：**

```powershell
python -m cli.main memorize "以后周报发给 A：python scripts/send_weekly.py --to a@example.com" --type "周报发送命令"
```

按回车。

> **字幕**：先记住一条旧决策：周报发给 A。

**输入新记忆（带否定词）：**

```powershell
python -m cli.main memorize "不对，以后周报发给 B：python scripts/send_weekly.py --to b@example.com" --type "周报发送命令"
```

按回车。

> **字幕**：说「不对，改成 B」—— 系统自动识别纠正意图。

**搜索验证：**

```powershell
python -m cli.main search "发送周报"
```

按回车。停 3 秒。

> **字幕**：旧记忆自动作废，只显示最新的发给 B 的命令。

**操作完成后，按回车继续。**

---

### 👆 步骤 4：工作流（30 秒）

> 脚本暂停，提示你手动操作

**保存工作流：**

```powershell
python -m cli.main workflow save "生产环境健康检查" "docker ps -a --filter name=api" "kubectl get pods -n prod" "curl -s http://api.prod.internal/health"
```

按回车。

> **字幕**：三步操作合成一个工作流。

**列出工作流：**

```powershell
python -m cli.main workflow list
```

按回车。

> **字幕**：下次一键执行，不用重复敲命令。

**操作完成后，按回车继续。**

## Part 2：飞书团队记忆（API 方向）

> 时长 ~3 分钟 | 脚本全自动，你看着就行
>
> 这部分用 API 模拟飞书群消息，展示后端处理逻辑

脚本会依次自动执行：

| 阶段 | 内容 | 字幕 |
|------|------|------|
| 飞书决策注入 | 3 条决策自动入库 | 模拟飞书群聊消息，机器人自动提取团队决策 |
| 消息路由 | 决策/查询/普通消息分类 | 三种消息，自动路由。决策入库，查询检索，闲聊忽略 |
| 飞书矛盾更新 | staging → prod | 飞书群里说「更正，用 prod」—— 旧决策自动失效 |
| 历史查询+跨域 | 部署查询 + docker 跨域 | 两个方向，一个记忆池，双向联动 |

---

### 👆 步骤 5：跨域 CLI 搜索（30 秒）

> 脚本暂停，提示你手动操作

**搜索「部署」：**

```powershell
python -m cli.main search "部署"
```

按回车。停 2 秒。

> **字幕**：飞书决策影响 CLI 推荐。搜「部署」，飞书入库的决策也会出现。

**搜索「docker」：**

```powershell
python -m cli.main search "docker"
```

按回车。停 2 秒。

> **字幕**：CLI 命令和飞书决策，共享同一个记忆池。

**操作完成后，按回车继续。**

## Part 3：飞书群聊真实交互

> 时长 ~4 分钟 | 全手动操作 | 展示真实的飞书群聊体验
>
> 这是整个 Demo 最"看得见"的部分——蓝色决策卡片在飞书群里弹出来

---

### 👆 步骤 6：启动飞书机器人（20 秒）

> 脚本会提示你打开终端 3

**打开终端 3，输入：**

```powershell
cd e:\feishu-long-memory-agent
python scripts/run_feishu_sdk_events.py
```

按回车。等看到 WebSocket 连接成功的日志。

> **字幕**：启动飞书机器人，通过 WebSocket 长连接监听群消息。

**切回终端 2，按回车继续。**

---

### 👆 步骤 7：飞书群聊 - 决策沉淀（60 秒）⭐ 核心亮点

> 脚本提示你操作飞书客户端

**打开飞书客户端，进入测试群。**

**发送第 1 条消息：**

```
以后前端统一用 TypeScript，不再使用 JavaScript
```

等 2-3 秒，观察机器人自动回复**蓝色决策卡片**。

> **字幕**：机器人自动识别决策意图，回复结构化卡片。蓝色 Header，包含主题、结论、推荐方案、废弃方案。

**发送第 2 条消息：**

```
API 接口统一用 RESTful，废弃 GraphQL
```

等机器人回复第二张蓝色卡片。

> **字幕**：每条决策自动入库，支持后续检索。

**发送第 3 条消息（含截止日期和项目名）：**

```
5月15日前完成代码规范统一，项目名 project-x
```

等机器人回复卡片，注意卡片中的截止日期。

> **字幕**：甚至能识别截止日期和项目名。

**操作完成后，切回终端 2，按回车继续。**

---

### 👆 步骤 8：飞书群聊 - 决策矛盾更新（40 秒）⭐ 核心亮点

> 脚本提示你操作飞书客户端

**在飞书群中发送：**

```
更正，前端统一用 Vue3，不再使用 TypeScript
```

等机器人回复新决策卡片。

> **字幕**：说「更正」—— 新决策自动覆盖旧决策。

**再发送查询消息：**

```
@机器人 查一下前端用什么框架
```

等机器人返回查询结果卡片。

> **字幕**：查到的是最新的 Vue3 决策，旧的 TypeScript 已被覆盖。团队永远执行最新方案。

**操作完成后，切回终端 2，按回车继续。**

---

### 👆 步骤 9：飞书群聊 - 查询 CLI 命令（30 秒）⭐ 核心亮点

> 脚本提示你操作飞书客户端

**在飞书群中发送：**

```
@机器人 怎么启动 webapp 容器
```

等机器人回复**绿色 CLI 命令卡片**。

> **字幕**：飞书群里问一句，机器人给出 CLI 里存的命令。绿色卡片，包含命令内容、使用频次、成功率。这就是跨域联动。

**操作完成后，切回终端 2，按回车继续。**
